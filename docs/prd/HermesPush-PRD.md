## 1 产品概述

### 1.1 背景

公司运营、财务、销售等团队每天产出大量周期性报表。现行做法是人工执行：连数据库跑 SQL，导出数据，粘贴进 Excel 模板，截图，发到企业微信群。单份报表耗时 30 到 60 分钟，人员休假时报表断档，数据口径靠个人记忆维持。

市场上有同类商业产品 EasySQLMail（成都国南新锐，2014 年起持续迭代），验证了这个需求形态：SQL 取数、模板填充、多格式输出、多渠道定时推送。开源领域调研了 Superset、Metabase、Redash、datart、DolphinScheduler、DataEase、JimuReport 等项目，没有任何一个同时覆盖上述链路，具体对照见第 11 章。

### 1.2 产品定位

HermesPush 是企业内部的数据推送平台。管理员接入数据源并授权，业务人员在界面上组装推送任务：SQL 数据集、渲染产物、推送渠道、调度策略。平台按计划自动执行，把查询结果渲染成 Markdown 摘要、Excel 文件、图片、PDF，发送到企业微信、钉钉、飞书群和邮箱。平台同时提供数据监控告警和按收件人个性化分发两类进阶能力。

平台不做 BI 分析。图表呈现依赖 Excel 模板自带的图表或 HTML 模板内的前端图表库，平台只负责取数、填充、渲染、分发。

### 1.3 产品目标与成功指标

| 指标 | 目标值 | 度量方式 |
|---|---|---|
| 推送成功率 | ≥ 99%（月度，剔除数据源自身故障） | 执行日志统计 |
| 单任务配置耗时 | ≤ 10 分钟（中位数，标准日报场景，按简单模式场景模板路径度量） | 前端埋点与用户回访 |
| 稳定运行任务数 | ≥ 100 个定时任务 | 任务表统计 |
| 人工时间替代 | 每个报表任务日均节省 ≥ 30 分钟 | 上线前后用户调研对比 |
| 平台可用性 | ≥ 99.5%（月度） | 心跳与监控 |
| 历史可复现性 | 任意一次历史执行可查到当时的任务版本、SQL 原文、参数、产物 | 抽查验证 |

### 1.4 范围

范围内（v1，按第 9 章里程碑分期交付）：

1. 数据源管理：MySQL、PostgreSQL、Oracle，加密存储，连通性测试，数据源级授权
2. SQL 数据集：在线编辑、参数与时间变量、安全校验、执行保护、数据预览
3. 模板管理：Excel / Markdown / HTML 三类模板，版本化，预置模板库
4. 产物渲染：Markdown、Excel、图片、PDF 四种产物，图片支持三种转换引擎，支持水印与长图切分，模板引擎沙箱化
5. 推送渠道：企业微信、钉钉、飞书群机器人，邮件 SMTP，通用 Webhook，共五类
6. 任务与调度：REPORT 定时报表、ALERT 数据监控两类任务，cron 调度（含 misfire 策略与高峰抖动），失败重试，手动触发与补数，试运行与测试发送
7. 个性化分发：分发清单驱动的按收件人循环推送
8. 存储与版本：本地 / S3 兼容对象存储 / HDFS 三种后端，任务配置快照与模板版本，产物归档与保留期
9. 治理：RBAC、SQL 审计、配置变更审计、账户安全、白名单、配额、错误码字典、今日概览、报表审核
10. 开放接口：入站触发 API、执行状态查询 API

范围外：

| 不做 | 理由 |
|---|---|
| BI 图表与自助分析 | 与推送平台定位冲突，属于 datart、DataEase 等产品领域 |
| 交互式查询界面（EasySQLMail 场景 5） | 同上。轻量取数由 SQL 预览和手动触发改参覆盖 |
| 数据血缘、元数据管理 | 超出范围 |
| 实时流式推送 | 定时批处理加分钟级 ALERT 评估已覆盖需求 |
| 字段级敏感数据脱敏 | 实现成本高、误判多。由只读账号和数据源级授权控制数据面 |
| 跨数据集级联传参 | 需要关联的场景在 SQL 内用 join 解决 |
| 多租户隔离 | 单组织内部平台 |
| 多任务工作流编排 | 复杂度过高。告警升级链、HTTP 命令完整版列入远期演进 |
| 企微通讯录 API 同步 | 需要企业应用级权限，与群机器人轻量接入方式不符。用静态通讯录管理替代 |
| 独立移动端界面 | 管理界面做响应式适配，执行详情可在手机浏览器查看 |

### 1.5 运行环境

多节点集群部署，部署形态为虚拟机或 Docker 容器（已确认，两者等效支持）。虚拟机路径提供部署手册（安装 Chromium、LibreOffice、Noto Sans CJK 字体的分步命令）；Docker 路径提供含渲染依赖的镜像（预计体积约 1.5GB），容器内 Chromium 需配置足够 `/dev/shm`（建议 ≥1GB）与沙箱参数（`--no-sandbox` 或 seccomp profile），LibreOffice profile 目录挂可写卷。转图拆独立 renderer 镜像/服务仍为演进路径，v1 单镜像交付。

元数据库 MySQL 8.0（`SKIP LOCKED` 语法为硬性依赖），缓存与分布式锁依赖 Redis。对象存储支持阿里云 OSS、MinIO（统一走 S3 兼容协议），HDFS 为可选模块（自建 Apache Hadoop 3.2.4，无 Kerberos）。图片与 PDF 渲染依赖 Chromium（Playwright 驱动），Excel 转图路线依赖 LibreOffice 与 Aspose（已有 18.9 授权 jar），中文字体必须随环境安装（统一字体清单以 Noto Sans CJK 为基准，开发与生产环境安装同款，规避跨平台渲染差异）。调度时区统一为 Asia/Shanghai，任务级时区配置列入远期。集群内所有调度与执行时间戳统一取数据库服务器时间，不信任应用节点本地时钟。

### 1.6 设计原则：渐进披露（v1.2 新增，一级原则）

v1.1 评审后功能达到 53 条 FR，用户试用原型的直接反馈是"复杂得不知道怎么使用"。功能齐全与上手简单靠分层兼得，本章为所有界面与交互需求的约束原则：

1. **默认极简**：新用户默认进入简单模式，只见日常高频功能（今日、任务、数据源、模板、渠道、执行记录六个入口）。建任务走场景模板或 3 步向导，全程不出现高级概念。
2. **高级折叠**：misfire 策略、cron 抖动、引擎回退、幂等键、数据就绪预检、审核策略等专家配置一律收进"高级"折叠面板，默认收起，收起时使用系统默认值。
3. **能力随里程碑渐显**：未交付里程碑的功能入口不在界面出现（ALERT、按人分发、审核工作台分别随 M4b、M5 上线才显示），避免界面展示用户用不到的东西。
4. **界面术语生活化**：文档术语与界面用语分离，界面不出现"产物、扇出、固版、状态跃迁"等词。对照表：

| 文档术语 | 界面用语 |
|---|---|
| 产物（Artifact） | 推送内容 |
| 数据集（Dataset） | 数据查询 |
| FANOUT / 子执行扇出 | 按人分发 |
| 固版（Pin） | 锁定版本 |
| ALERT 状态跃迁 | 触发提醒 / 恢复提醒 |
| bizDate | 数据日期 |
| 渲染引擎 / provider | 图片生成方式 |
| 试运行 / 测试发送 | 先看看效果 / 发到测试群 |
| RETRY_WAIT / 幂等 | 自动重试（界面只说"失败会自动重试 3 次"） |

5. **两种模式一份数据**：简单模式与专家模式操作的是同一份任务配置，专家模式是简单模式的全集视图，切换不丢数据、不产生副本。

本章原则的验收载体是 FR-OPS-05 与原型 `docs/prototype/index.html`（默认简单模式）。

## 3 业务流程

### 3.1 定时报表推送（REPORT 任务）

```
Quartz 按 cron 触发（集群内仅一个节点生效，misfire 策略见 FR-EXE-01）
  → 解析业务日期 bizDate，写入执行记录（状态 PENDING，唯一索引防重复）
  → Worker 按优先级从队列领取（FOR UPDATE SKIP LOCKED），置 RUNNING，启动心跳
  → 加载任务配置快照（固版优先，否则最新版；领取时校验任务仍为上线状态）
  → 逐数据集执行 SQL：参数绑定、行数与超时保护、写 SQL 审计
  → 空结果判定：SKIP / PUSH_PLACEHOLDER / FAIL
  → 按依赖拓扑顺序渲染产物：单个产物渲染失败不阻断其余产物
  → 逐渠道逐产物推送：幂等检查、令牌桶限流、素材缓存、逐条记录；渲染失败的产物跳过
  → 产物上传存储归档，写逻辑 URI
  → 汇总执行状态，清理本地临时文件
  → 失败且可重试：原执行记录置 RETRY_WAIT 并计算下次重试时间（复用同一执行 ID）
  → 重试耗尽：发系统告警（去重静默）
```

### 3.2 数据监控告警（ALERT 任务）

```
Quartz 按评估周期触发（最小 1 分钟；错过触发点立即补评估一次）
  → Worker 领取，执行监控 SQL（走同一套校验、保护、审计）
  → 取结果值与阈值比较，得到本次判定 hit / miss（NULL 与 0 行均按 miss）
  → 防抖：连续 N 次 hit 才认定 TRIGGERED（计数更新走乐观锁）
  → 读取告警状态表：
      状态未变化：仅更新最近值，不通知
      OK → TRIGGERED：发送告警通知（含触发值、阈值、时间、任务链接）
      TRIGGERED → OK：发送恢复通知
  → 更新状态表，写执行日志
  → 执行终态：查询与评估成功即 SUCCESS（是否发送通知是业务语义，不影响执行成败）
```

### 3.3 个性化分发（FANOUT，REPORT 任务的可选能力）

```
父执行触发
  → 加载任务快照，执行清单 SQL 或读取静态清单
  → 清单为空：按任务空结果策略处理；清单行按 fanout_key 哈希去重，重复行保留首条并记 WARN
  → 校验清单行数不超过上限（默认 200），超限则失败并告警
  → 每行扇出一个子执行（记录 parent_exec_id 与 fanout_key），行字段注入为该子执行的运行时参数
  → 父执行置 WAIT_CHILDREN，释放 Worker
  → 子执行进入普通队列并行处理，各自完成查询、渲染（水印可引用行字段）、推送、重试、幂等
  → 每个子执行到达终态时尝试以条件更新（CAS）汇总父执行状态，最后一个完成的子执行触发终判
  → 父执行终态：全部成功 SUCCESS，部分成功 PARTIAL_SUCCESS（列出失败行），全部失败 FAILED
```

### 3.4 手动触发与补数

用户在任务详情页点击"手动触发"，弹窗展示本次生效的全部参数（时间变量按当前日期解析），允许覆盖 bizDate 与静态参数。bizDate 必须为 yyyy-MM-dd 格式，前端拦截加后端二次校验。提交后写入一条 trigger_type 为 MANUAL 的执行记录，进入同一队列。同一秒重复提交由幂等键区分：手动触发默认生成幂等键（任务 ID + bizDate + 提交序号），调用方也可显式传入。补跑历史日期的操作路径与手动触发相同，仅修改 bizDate；批量区间补数列入远期。

### 3.5 试运行与测试发送

术语约定（评审修订，全文统一）：
- 数据预览：SQL 编辑器内的单条查询试跑，只写 SQL 审计（scene = PREVIEW），不产生执行记录
- 试运行：任务级完整链路验证，执行全部数据集并渲染全部产物，产生执行记录（trigger_type = TRIAL），SQL 审计 scene = TRIAL，不发生推送
- 测试发送：完整推送链路验证，产生执行记录（trigger_type = TEST），目标仅限测试渠道或本人邮箱，消息带"[测试]"前缀

规则：任务每次保存产生新版本后，上线前必须对当前最新版本试运行通过；固版运行要求该版本存在试运行成功记录。测试发送次数计入每日配额（FR-OPS-03）。

## 4 功能需求

### 4.1 数据源管理

#### FR-DS-01 数据源维护（P0 / M1）

支持 MySQL、PostgreSQL、Oracle 三种类型的新增、编辑、启用、停用。连接信息含 JDBC URL、用户名、密码、连接池参数（最大连接数默认 5，可配）。密码 AES-GCM 加密存储，任何接口不回显明文，编辑时留空表示不修改。停用数据源时校验引用：存在运行中任务引用则提示影响面并要求确认。

验收：
1. 新增一个 MySQL 数据源，数据库中密码字段为密文（格式含 key_id，见 FR-SEC-01），接口响应无明文
2. 停用被引用数据源时出现影响面提示

#### FR-DS-02 连通性测试（P0 / M1）

界面按钮触发建连并执行 `SELECT 1`，返回耗时与数据库版本信息。失败时返回分类错误（网络不通、认证失败、库不存在），映射错误码 DS-001/002/003。

验收：断开网络后测试，10 秒内返回 DS-002 与可读提示。

#### FR-DS-03 只读账号约束（P0 / M1）

数据源表单展示强制提示"必须使用只读账号"，要求勾选"已确认该账号无写权限"后才允许保存，勾选记录进配置变更审计。平台不做在线写权限探测（各数据库探测方式差异大、有副作用风险），防线由账号管控、SQL 白名单校验、审计三层构成。

验收：未勾选确认时保存按钮不可用。

#### FR-DS-04 执行保护（P0 / M1）

数据源级配置：查询超时（默认 60 秒）、单次查询行数上限（默认 50000）、超限行为（截断并告警 / 直接失败，默认截断）。执行时通过 `queryTimeout`、`maxRows`、`fetchSize` 流式读取实现，不拼接 LIMIT。

验收：构造 6 万行结果的查询，执行在行数上限处停止，产物标注"已截断"；构造 sleep 查询，超时后 5 秒内返回 DS-002。

#### FR-DS-05 数据源级授权（P0 / M2）

授权表支持按用户、按角色授予数据源使用权限。DEVELOPER 编写数据集时只能选择已授权数据源。新建数据源默认不授权给任何非 ADMIN 用户。评审修订：由 M4 提前至 M2，与基础 RBAC 同期生效（M2 起平台具备文件外发能力，不能继续单管理员模式）。

### 4.2 SQL 数据集

#### FR-SQL-01 SQL 编辑与安全校验（P0 / M1）

Monaco 编辑器，SQL 语法高亮。保存与执行前经 Druid SQL Parser 校验：必须是单条 SELECT 语句（允许 WITH 子句），拒绝 DDL、DML、多语句、注释绕过。校验失败给出定位到关键字的报错，并写入 SQL 审计（scene = VALIDATION_FAILED，评审修订：失败尝试同样留痕，供安全追溯）。

验收：
1. `SELECT ...; DROP TABLE ...` 被拒绝，报错指明多语句，审计出现 VALIDATION_FAILED 记录
2. `UPDATE`、`DELETE`、`INSERT` 开头的语句被拒绝
3. 合法 SELECT 与 WITH 查询通过

#### FR-SQL-02 参数与时间变量（P0 / M1）

参数语法两种：`#{param}` 走 PreparedStatement 绑定，为默认推荐方式；`${param}` 走文本替换，仅限表名、IN 列表等无法绑定的场景，需在参数定义上显式勾选"允许文本替换"，且值必须匹配参数定义中配置的白名单或正则，不匹配则执行失败（错误码 SQL-005）。

参数取值来源三级，优先级由低到高：
1. 内置时间变量。语法 `#{name[±N(d|w|M|y)][:pattern]}`。name 支持 runDate（触发时刻日期）与 bizDate（业务日期，等于 runDate 加任务级偏移）。任务级偏移单位固定为天，默认 -1 天，界面明示单位
2. 任务级静态参数，键值对形式在任务配置中维护
3. 运行时入参：手动触发弹窗覆盖，FANOUT 场景由清单行注入，API 触发由请求体传入

用户定义的静态参数与内置时间变量重名时，保存校验拒绝并提示（评审修订：避免优先级歧义）。必填参数缺失时执行失败（错误码 SQL-004），错误信息指向具体参数。

#### FR-SQL-03 数据预览（P0 / M1）

编辑器旁"预览"按钮执行当前 SQL（参数弹窗填写），返回前 200 行数据与字段结构（字段名、类型），用于产物配置的字段绑定提示。预览执行写入 SQL 审计，scene 为 PREVIEW，不产生执行记录（术语见 3.5）。预览权限：ADMIN 与 DEVELOPER，VIEWER 不可。

#### FR-SQL-04 结果集统一模型（P0 / M1，内部需求）

查询结果统一为 DatasetResult：列元数据、总行数、是否截断，行数据提供两种访问方式：随机访问 List（小结果集，阈值 5000 行以内）与顺序迭代器（`forEachRow` 流式消费，大结果集）。评审修订：Excel 渲染器必须走迭代器分批消费，禁止先物化全量 List 再渲染，否则流式读取失效。类型映射：日期时间转 ISO 字符串与时间戳双字段，数值保留原始精度，NULL 转空值并在模板层提供默认值函数。

### 4.3 模板管理

#### FR-TPL-01 模板上传与类型（P0 / M2）

模板类型三种：EXCEL（.xlsx，上限 20MB）、MARKDOWN（.md 文本，上限 256KB）、HTML（.html 或 .ftl 文本，上限 256KB）。上传时校验扩展名与文件头。文本类模板上传即执行 Freemarker 沙箱扫描（FR-RD-10），含危险指令的模板拒绝入库。模板归属平台级（跨任务可引用），创建人与最近修改人记录在案。

#### FR-TPL-02 模板版本（P0 / M2）

每次上传生成新版本号（自增），历史版本不可变，可下载。回滚操作以历史版本内容创建新版本，不修改历史记录。版本列表展示版本号、大小、校验和、上传人、时间、备注。

删除规则（评审修订）：模板与模板版本仅允许逻辑删除（archived 标记），文件永不物理删除，保障历史执行可复现。删除前校验引用：存在任务（含固版快照）引用时禁止删除并列出影响面。

#### FR-TPL-03 模板预览（P1 / M2）

MARKDOWN 与 HTML 模板直接预览源码与渲染占位效果；EXCEL 模板展示 sheet 结构与占位符清单（解析 `{}` 语法提取变量名）。

#### FR-TPL-04 预置模板库（P1 / M2）

系统内置 5 个示例模板：日报摘要（Markdown）、销售明细（Excel）、KPI 看板（HTML）、告警通知文本（Markdown）、周报（Markdown）。示例模板可一键复制为用户模板，并可从示例直接创建带样例数据集的任务骨架。所有预置模板必须通过 FR-RD-10 沙箱扫描。

#### FR-TPL-05 默认 HTML 表格模板生成（P1 / M3）

在产物配置中选择数据集后，平台按列元数据自动生成一份带基础样式的 HTML 表格模板（表头、斑马纹、数值右对齐、日期格式化），用户可下载修改后回传，回传同样过沙箱扫描。

### 4.4 产物渲染

#### FR-RD-01 产物定义（P0 / M1）

产物 = 类型（MARKDOWN / EXCEL / IMAGE / PDF）+ 模板 + 渲染配置 + 数据集引用。一个任务下产物数量上限 10 个。产物间可声明依赖：IMAGE 与 PDF 产物的 source 可指向另一个 EXCEL 产物（文件转图路线）或 HTML 模板（网页渲染路线）。渲染按依赖拓扑排序执行，保存任务时做环检测，存在循环依赖拒绝保存并提示环路（评审修订）。

渲染部分成功语义（评审修订）：单个产物渲染失败记录错误码，不阻断其余产物渲染；推送阶段跳过渲染失败的产物；执行终态汇总规则：至少一个产物成功推送至至少一个渠道为 PARTIAL_SUCCESS 或 SUCCESS（全部绑定组合成功为 SUCCESS），全部推送失败为 FAILED。

#### FR-RD-02 Markdown 渲染（P0 / M1）

Freemarker 模板引擎（沙箱配置见 FR-RD-10）。数据访问语法：单值 `${ds1.rows[0].amount}`，循环 `<#list ds1.rows as r>`。内置格式化函数：千分位（fmtNumber）、百分比（fmtPercent）、日期（fmtDate）、空值默认（dft）。

模板引用不存在的数据集字段时渲染失败，错误码 TPL-003，信息指出模板行号与字段名；试运行时对模板变量与数据集字段做匹配预检，提前暴露该类错误（评审修订）。

输出长度约束按 UTF-8 字节数计算（评审修订：中文每字 3 字节，界面向用户提示约合字数）：企微 text 2048 字节（约 680 汉字）、markdown 4096 字节（约 1360 汉字），钉钉飞书按各自上限，阈值全部配置化，实现时以官方文档核对。超长处理策略可配：
1. 截断加提示（默认）
2. 转文件发送：完整文本生成 .md 文件走渠道 file 消息类型；绑定的渠道不支持 file 类型时该策略在保存时校验拦截（评审修订：明确落地语义）
3. 失败

#### FR-RD-03 Excel 渲染（P0 / M2）

EasyExcel 模板填充。占位符语法规范（评审修订，M2 前置 spike 验证后冻结）：
1. 列表填充：`{.字段名}`，与 `FillWrapper("数据集名", 行迭代器)` 配套，列表占位符所在 sheet 与 FillWrapper 名称一一对应；多列表同 sheet 使用 forceNewRow，spike 不通过则约束为一个 sheet 一个列表
2. 单值填充：`{数据集名.字段名}`，取该数据集第一行对应字段，由平台自定义解析器在填充前替换
3. 行数超过 10000 时经迭代器分批填充（FR-SQL-04），禁止全量物化

填充后文件写入本地临时目录，随后归档上传。

验收：5 万行 × 20 列数据、标准明细模板、8 核 16G 单节点环境下填充完成时间 ≤ 30 秒，堆内存峰值增量 ≤ 1GB（评审修订：性能指标绑定基准场景）。

#### FR-RD-04 图片渲染（P0 / M3）

IMAGE 产物两条 source 路径：

| source | 模板 | 转换引擎 | 说明 |
|---|---|---|---|
| HTML_TEMPLATE | HTML 模板 | HTML_SHOT（Playwright 截图，默认） | 样式完全由模板 CSS 控制，长图与响应式宽度天然支持 |
| ARTIFACT_REF | 引用的 EXCEL 产物 | LIBREOFFICE 或 ASPOSE，全局默认加产物级覆盖 | 文件与图同源。Aspose 使用公司已有 aspose-cells-18.9.jar，License 文件加载失败或 JDK 21 兼容 spike 不通过时该 provider 不注册、界面置灰 |

引擎故障回退（评审修订）：ARTIFACT_REF 路线支持配置引擎优先级列表（如 [LIBREOFFICE, ASPOSE]），主引擎发生可重试类故障（进程超时、崩溃）时自动尝试下一引擎，产物明细记录实际使用引擎与回退原因。

图片后处理：
1. 长图切分：超过最大高度（默认 4096px）自动切分
2. 压缩终止条件（评审修订）：质量自 90% 起按 10% 步长降至 30%，仍超限则分辨率按 0.8 倍逐级下调至最小宽度 400px，仍超限执行失败，错误码 RD-006
3. DPI 可配，默认 2x

#### FR-RD-05 PDF 渲染（P1 / M3）

PDF 产物两条路线：HTML_PRINT（默认，Playwright page.pdf()，支持页眉页脚与分页控制）；LIBREOFFICE（EXCEL 产物转 PDF）。M3 阶段 PDF 的消费路径为企微 file 消息（M2 已交付）与执行日志下载；M4b 邮件渠道交付后作为附件主渠道。PDF 加密、禁打印、禁复制列入远期演进。

#### FR-RD-06 图片行数上限与降级（P0 / M3）

IMAGE 产物独立行数上限，默认 200 行，超限策略三选一：
1. TRUNCATE_TOP_N：渲染前 N 行，图内标注"仅显示前 N 行，完整数据见附件"
2. DEGRADE_TO_FILE：该渠道改发 Excel 文件。前置校验（评审修订）：要求同任务存在与该 IMAGE 同源的 EXCEL 产物且该渠道已绑定其为 file 消息，不满足时该策略保存拦截
3. FAIL：执行失败

#### FR-RD-07 图片水印（P2 / M3）

HTML_SHOT 路线支持模板级水印配置：文字内容支持变量（任务名、bizDate、接收人、FANOUT 清单行字段），斜排半透明 CSS 实现。水印变量解析失败时替换为空字符串并记 WARN，不阻断渲染（评审修订）。EXCEL 与 LIBREOFFICE 路线的水印列入远期。

#### FR-RD-08 渲染效果对比页（P2 / M3）

选择一个任务与业务日期，并行用可用引擎渲染，结果并排展示，可下载。用于评估各引擎对真实模板的还原效果，决定全局默认引擎。

#### FR-RD-09 渲染进程管理（P0 / M3，内部需求）

Chromium 与 LibreOffice 均为外部进程：
1. 进程池复用；LibreOffice 每进程处理 50 个请求后销毁重建（防内存泄漏，评审修订）；进程退出后清理其临时目录
2. 节点级并发信号量（默认 2），渲染并发为节点级配置，集群总并发随节点数线性扩展（评审修订：明确全局配额与节点并发的关系，见 FR-OPS-03）
3. 单任务进程超时强杀（默认 120 秒）
4. LibreOffice 每进程独立 UserInstallation 目录
5. 渲染接口无本地状态，支持未来拆分独立渲染服务

M3 前置 spike（评审修订）：在目标部署环境（Linux 容器）验证 Playwright 截图字体渲染与 CSS 还原度，Windows 开发环境安装同款字体（Noto Sans CJK）对齐效果。

#### FR-RD-10 模板引擎沙箱（P0 / M1，内部需求，评审新增）

用户可上传的 Freemarker 模板（Markdown / HTML / Webhook 请求体）存在远程代码执行风险：默认配置下模板可通过 `?new` 构造任意 Java 对象、通过 `?api` 调用对象方法。强制沙箱配置：
1. TemplateClassResolver 设为 ALLOWS_NOTHING_RESOLVER，禁用 `?new`
2. api_builtin_enabled 设为 false，禁用 `?api`
3. 禁用 `ObjectConstructor`、`Execute`、`JythonRuntime` 等危险内建
4. 模板上传与导入时静态扫描危险指令（`?new`、`?api`、`freemarker.template.utility` 等关键字），命中拒绝入库
5. 渲染超时保护（模板死循环），默认 30 秒

验收：包含 `<#assign ex="freemarker.template.utility.Execute"?new()>${ex("whoami")}` 的模板上传被拒绝；绕过扫描入库的同类模板渲染时抛沙箱异常，错误码 TPL-010。

### 4.5 推送渠道

#### FR-CH-01 渠道维护与凭据加密（P0 / M1）

渠道实体含类型、名称、连接配置（加密存储）、限流阈值、状态、测试渠道标记。五类渠道的连接配置：

| 类型 | 配置项 | 里程碑 |
|---|---|---|
| WEWORK_BOT | webhook 地址 | M1 |
| DINGTALK_BOT | webhook 地址、加签 secret | M4b |
| FEISHU_BOT | webhook 地址、加签 secret（可选） | M4b |
| EMAIL_SMTP | SMTP 主机、端口、SSL/TLS、发件账号、密码 | M4b |
| GENERIC_WEBHOOK | 目标 URL、自定义 Header、Basic Auth、HMAC 签名密钥、请求体模板 | M5 |

渠道为逻辑删除（评审修订）：被任务绑定或历史执行引用的渠道不可物理删除，删除后在任务配置中置灰提示"渠道已删除"。

#### FR-CH-02 企业微信机器人推送（P0 / M1 起分步）

消息类型与里程碑：text、markdown（M1）；file（M2，经 upload_media 换 media_id）；image（M3，base64 加 md5，JPG/PNG 格式，不超过 2MB）。官方限制（已核实）：文件不超过 20MB，media_id 有效期 3 天，单机器人 20 条每分钟，markdown 上限 4096 字节按 UTF-8 计。支持 mentioned_list @ 群成员（标识类型 userid 或手机号，实现时以官方文档核对，FANOUT 清单 receiver 列语义与此对齐）。

#### FR-CH-03 渠道健康检查（P1 / M1）

渠道详情页"发送测试消息"按钮，向该渠道发一条带时间戳的测试文本，返回成功或分类错误（webhook 失效、加签错误、网络不通、被限流）。健康检查不计入渠道限流配额的告警统计。

#### FR-CH-04 Webhook 域名白名单（P0 / M1）

机器人渠道与 GENERIC_WEBHOOK 的目标地址 host 必须在白名单内，白名单初始值为 qyapi.weixin.qq.com、oapi.dingtalk.com、open.feishu.cn，仅 ADMIN 可增删。校验时机双重（评审修订）：渠道保存时校验；每次发送前实时校验（防白名单事后被删或 DNS 变更导致外流）。白名单条目删除时校验引用，被启用渠道引用的条目不可删除。白名单数据独立建表（type 区分 WEBHOOK_HOST / EMAIL_DOMAIN / EMAIL_ADDRESS），增删改写配置审计。

#### FR-CH-05 分布式限流（P0 / M1）

Redisson 令牌桶，key 按 webhook 地址的 SHA-256 摘要（评审修订：明确摘要算法；同一机器人被多个渠道配置引用时共享额度）。阈值默认值按渠道类型配置化（企微 20 每分钟，钉钉飞书以官方文档核对后设定）。超限行为为排队等待，等待超时（默认 5 分钟）后按可重试失败处理（错误码 PUSH-011）。限流为近似值，误差秒级（Redis 与各节点时钟偏差），文档明示。

验收：单渠道 1 分钟内提交 30 条推送，前 20 条即时发出，其余排队在下一分钟窗口发出，无 45009 类限流错误。

#### FR-CH-06 渠道级部分成功与幂等（P0 / M1）

一次执行推送多个渠道时逐渠道记录成败。幂等键为（执行 ID，渠道 ID，产物标识，消息类型）四元组（评审修订：增加消息类型维度，支持同一产物先图片后降级文件等多消息类型场景）。重试复用原执行 ID（见 FR-EXE-04），已成功的四元组组合重试时跳过。执行终态：全部成功 SUCCESS，部分成功 PARTIAL_SUCCESS，全部失败 FAILED。

#### FR-CH-07 素材缓存（P0 / M2）

企微 media_id 与飞书 image_key 按（渠道，文件 md5）缓存，命中未过期缓存时跳过上传。企微缓存有效期按官方时限的 80% 设定（media_id 3 天，缓存 2.4 天）；飞书 image_key 有效期以官方文档核对后设定（待验证项，见第 10 章）。

#### FR-CH-08 钉钉机器人推送（P1 / M4b，能力待验证）

评审修订：钉钉自定义机器人（群 webhook）公开文档显示支持 text、markdown、link、actionCard、feedCard，不支持 file 消息类型，图片需以公网可访问 URL 形式嵌入 markdown。本条能力范围在 M4b 启动前以官方文档与真机验证冻结，当前按以下降级设计：
1. 支持消息类型：text、markdown、link、actionCard
2. 图片产物：经平台 presignedUrl 生成短时效下载地址嵌入 markdown 图片语法（要求群成员网络可达平台地址）；不可达时该产物在钉钉渠道置灰
3. Excel 与 PDF 文件产物：钉钉渠道不支持，绑定界面明示，文件需求引导走邮件渠道
4. 加签：timestamp 加 HmacSHA256 sign
若验证结论与上述不符，以验证结论修订本条。

#### FR-CH-09 飞书机器人推送（P1 / M4b，能力待验证）

评审修订：飞书自定义机器人公开文档显示支持 text、post（富文本）、image（先上传获取 image_key）、share_chat、interactive（卡片），file 类型是否对自定义机器人开放待验证。当前按以下设计：
1. 支持消息类型：text、post、image、interactive
2. file 能力待官方文档与真机验证，不支持则同 FR-CH-08 第 3 条处理
3. 支持可选加签
4. image_key 有效期与复用策略验证后定缓存方案（FR-CH-07）

#### FR-CH-10 邮件渠道（P1 / M4b）

能力：收件人与抄送列表；HTML 正文（可直接绑定 MARKDOWN 或 HTML 产物渲染结果）；附件（Excel、PDF、图片产物，从存储拉取）；主题模板支持变量（任务名、bizDate）。

管控与边界（评审修订）：
1. 收件人域名或完整地址白名单，仅 ADMIN 维护，发送前逐地址实时校验，名单外地址拒发并记录审计
2. 附件总大小上限默认 20MB，超限执行失败，错误码 PUSH-022，提示减少附件或调大上限（不做自动拆包）
3. SMTP 连接失败可重试，地址被拒（550 等）不可重试（错误码 PUSH-021）

#### FR-CH-11 消息回链（P1 / M4b）

系统设置中配置 platformBaseUrl 后，推送消息尾部自动追加"查看执行详情"链接，指向本次执行的详情页。链接带访问者权限校验，未登录跳转登录页。FANOUT 子执行的链接指向子执行详情。群机器人渠道要求群成员网络可达平台地址，不可达时任务级关闭回链。

#### FR-CH-12 通用 Webhook 渠道（P2 / M5）

把执行结果 POST 到指定 HTTP 端点。请求体为 Freemarker 模板（沙箱同 FR-RD-10），可引用执行元信息与产物信息（类型、行数、存储下载地址）。支持自定义 Header 与 Basic Auth。

请求签名（评审修订）：支持渠道级 HMAC-SHA256 签名，签名值置于 X-HermesPush-Signature 头，接收方可验证请求来源，与入站 API 的 token 鉴权形成对称。目标 URL 受 FR-CH-04 白名单管控（白名单支持 host 加路径前缀粒度），新增端点需 ADMIN 审批。超时默认 10 秒，失败进入统一重试体系。

#### FR-CH-13 通讯录管理（P2 / M5）

维护邮件联系人（姓名、邮箱、部门）与群目录（群名、渠道、用途）。FANOUT 静态清单与邮件渠道收件人可从通讯录选择。支持 CSV 批量导入，导入地址自动比对收件人白名单，名单外地址标红提示。不做企微通讯录 API 同步（见 1.4）。

### 4.6 任务管理

#### FR-TSK-01 任务创建向导（P0 / M1，专家模式）

本条描述专家模式的完整五步向导。简单模式入口（场景模板与 3 步向导）见 FR-OPS-05，两种模式产出同一份任务配置数据，简单模式未触及的配置项取系统默认值（bizDate 偏移 -1 天、空结果 SKIP、重试 3 次、无审核、无预检、misfire 默认策略）。

五步向导：
1. 数据集：选择数据源（仅已授权），编写 SQL，定义参数，预览数据。可添加多个数据集（上限 10）
2. 产物：选择类型与模板，绑定数据集，配置渲染参数（行数上限、超长策略、水印、引擎回退列表）
3. 渠道：选择渠道，为每个渠道勾选产物与消息类型（保存时校验渠道能力与产物类型匹配，如钉钉不可绑 file）
4. 调度：cron（未来 5 次预览、常用模板、高峰抖动开关）、bizDate 偏移、超时、重试、空结果策略、misfire 策略
5. 试运行：执行查询与渲染，预览全部产物，可发起测试发送

任务基本信息（名称、描述、标签、负责人）在第一步前填写。向导各步支持保存草稿。

#### FR-TSK-02 试运行与测试发送（P0 / M1）

语义与规则见 3.5 节（评审修订：试运行状态按任务版本计，每个新版本上线前须试运行通过；固版须有对应版本的试运行成功记录）。测试发送目标仅限 ADMIN 标记"测试用途"的渠道或当前用户邮箱。

验收：
1. 新建任务在向导第 5 步能看到全部数据集与产物的渲染预览
2. 测试发送后测试群收到带"[测试]"前缀的消息，执行日志出现 TEST 记录
3. 未对当前版本试运行的任务，上线按钮置灰并提示

#### FR-TSK-03 任务生命周期（P0 / M1）

状态：草稿、已上线、已下线、已暂停。上线校验：至少一个数据集、一个产物、一个渠道绑定、cron 合法、当前版本已试运行通过。下线任务保留历史执行记录。删除为逻辑删除，仅 ADMIN 或任务负责人可删，已上线任务需先下线。

下线与在途执行的联动（评审修订）：任务下线时，其全部 RETRY_WAIT 执行记录置 CANCELLED；Worker 领取执行时校验任务状态，非上线状态直接置 CANCELLED 不执行。

#### FR-TSK-04 手动触发与补数（P0 / M1）

见 3.4 节。手动触发支持覆盖 bizDate 与任意静态参数，弹窗展示覆盖前后参数对照。bizDate 格式强校验（yyyy-MM-dd）。触发写入 MANUAL 执行记录，携带幂等键防重复提交。

#### FR-TSK-05 任务配置版本（P0 / M2）

每次保存生成新版本快照（JSON，含数据集 SQL、参数、产物、渠道绑定、调度、分发清单、告警条件、引用的模板版本号与模板文件校验和）。快照冗余模板 checksum 与 storage_uri（评审修订：即使模板后续被归档，历史执行仍可定位文件）。

任务可固版（pinned）：调度执行使用固版快照，编辑产生新版本但不影响运行，解除固版后回到最新版。版本列表支持任意两版本字段级 diff 与回滚（回滚即以历史快照创建新版本）。每次执行记录关联具体版本号。

并发编辑保护（评审修订）：任务表带乐观锁版本字段，保存时比对，冲突则提示"任务已被他人修改，请刷新后重试"。

#### FR-TSK-06 任务复制（P1 / M2）

复制任务生成新草稿，名称加"副本"后缀，数据集、产物、渠道绑定、调度全部带过来，版本历史与试运行记录不带（新任务须重新试运行后上线）。

#### FR-TSK-07 空结果集策略（P0 / M2）

任务级配置三选一：SKIP（不推送，执行记为成功并标注"空结果跳过"）、PUSH_PLACEHOLDER（推送占位文案，文案可配，默认"今日无数据"）、FAIL（执行失败）。判定口径（评审修订）：默认全部数据集均无行为空；可指定若干数据集为判定依据，指定的数据集全部为空才判空（ALL 语义）。FANOUT 清单为空时复用本策略。

#### FR-TSK-08 标签与批量操作（P2 / M4a）

任务支持多标签（业务线、报表类型），列表按标签与状态筛选。批量操作：上线、下线、暂停、打标签，单次上限 50 个，操作写配置审计。

#### FR-TSK-09 配置导出导入（P1 / M4a）

任务可导出为 JSON 文件（含任务快照、引用的模板文件、依赖的数据源与渠道名称清单，不含任何凭据）。导入安全规则（评审修订）：导入的 SQL 重新经 Druid 校验，模板内容重新经 Freemarker 沙箱扫描，与在线创建走同一套防线；数据源与渠道按名称匹配，匹配不到的逐项手工指定。导入导出操作写配置审计。用途：环境迁移、离职交接、任务备份。

#### FR-TSK-10 报表审核（P2 / M5）

任务可配置审核策略：免审核（默认）/ 指定审核人（一人或多人会签）。配置审核的任务执行到产物渲染完成后进入 WAIT_APPROVAL 状态，审核人在审核工作台预览产物，批准后继续推送，驳回则执行终止（CANCELLED，驳回原因必填，写审计）。审核超时（默认 2 小时）按任务配置处理：放弃本次推送或降级免审核推送。WAIT_APPROVAL 期间不占用 Worker（挂起态，批准动作重新入队推送阶段）。

### 4.7 调度与执行

#### FR-EXE-01 Cron 调度（P0 / M1）

标准 Quartz cron 表达式，时区固定 Asia/Shanghai。保存时校验合法性并展示未来 5 次触发时间。最小调度间隔 1 分钟。

集群防重（评审修订）：执行记录唯一索引为（task_id, fire_time, trigger_type, idempotency_key），CRON 触发幂等键为空串占位，FANOUT 子执行使用独立唯一键（parent_exec_id, fanout_key），不受本索引约束。

misfire 策略（评审修订，任务级可配）：REPORT 任务错过触发点超过 1 个周期不补发（do nothing），错过 1 个周期以内立即补发一次；ALERT 任务错过则立即补评估一次。节点宕机恢复后不允许批量补发历史触发点。

高峰抖动（评审修订）：任务可开启 cron 抖动，触发时间在配置时刻基础上加 0 到 5 分钟随机偏移（偏移量对同一任务当日固定，写入执行记录），用于打散整点高峰，见第 5 章峰值指标。

#### FR-EXE-02 执行队列与 Worker（P0 / M1）

调度器只负责写入 PENDING 执行记录。各节点 Worker 池通过 `SELECT ... FOR UPDATE SKIP LOCKED ... LIMIT 1` 领取执行（评审修订：LIMIT 1 缩小锁范围；领取 SQL 手写 XML 维护并配单元测试，不经 MyBatis-Plus 封装，见第 8 章）。

队列优先级（评审修订）：执行记录带 priority 字段，领取按 `ORDER BY priority DESC, fire_time ASC`。默认优先级：ALERT 评估高于 REPORT（ALERT 轻量、时效敏感），REPORT 内手动触发与重试高于定时首次执行。防止高频 ALERT 或大批量定时任务互相饿死。

并发：单节点 Worker 并发默认 4（虚拟线程），渲染并发为节点级信号量（FR-RD-09），全局配额见 FR-OPS-03。定时触发、手动触发、失败重试、API 触发、FANOUT 子执行统一走该队列。

队列维护（评审修订）：执行记录 180 天后移入归档表，保障队列表扫描性能。

#### FR-EXE-03 执行状态机（P0 / M1）

状态：PENDING、RUNNING、RETRY_WAIT、WAIT_CHILDREN（FANOUT 父执行，M5）、SUCCESS、PARTIAL_SUCCESS、FAILED、TIMEOUT、CANCELLED，M5 增加 WAIT_APPROVAL。任务级执行超时（默认 10 分钟）到期置 TIMEOUT 并按可重试处理。ALERT 任务查询与评估成功即 SUCCESS，是否发送跃迁通知不影响执行终态（评审修订）。

#### FR-EXE-04 失败重试（P0 / M1）

错误分两类。可重试：数据源连接失败、查询超时、渠道服务端错误、限流等待超时、素材上传失败、SMTP 连接失败、渲染进程超时。不可重试：SQL 语法错误、模板解析与沙箱错误、必填参数缺失、webhook 失效、图片超限、邮件地址被拒、附件超限。

重试模型（评审修订，消除原版本矛盾）：重试复用原执行记录，不生成新执行 ID；原记录置 RETRY_WAIT 并写 retry_count 与 next_retry_at，到期由巡检置回 PENDING 重新领取。幂等键（执行 ID，渠道，产物，消息类型）在重试间保持不变，已成功的推送组合天然跳过。默认重试 3 次，退避 30 秒、2 分钟、8 分钟，次数与间隔任务级可配。next_retry_at 以数据库时间计算（评审修订：不信任节点本地时钟）。

#### FR-EXE-05 执行日志（P0 / M1）

每次执行记录：触发方式（CRON / MANUAL / TEST / TRIAL / RETRY / API / FANOUT 子执行）、任务版本、bizDate、生效参数快照（标记为敏感的参数值脱敏存储）、各数据集行数与耗时、各产物明细（类型、引擎、行数、大小、存储 URI、耗时、回退记录）、各渠道推送明细（状态、错误码、重试次数）、总耗时、错误码。列表支持按任务、状态、时间、触发方式筛选。产物在保留期内可下载。

#### FR-EXE-06 执行详情阶段时间线（P1 / M4a）

详情页以横向时间线展示各阶段耗时：排队、查询（分数据集）、渲染（分产物）、推送（分渠道），异常阶段红色标注并直连错误详情。

#### FR-EXE-07 心跳与僵死恢复（P0 / M4a，M1 以执行超时兜底）

Worker 领取执行后写入节点标识并每 30 秒更新心跳，心跳超时阈值 2 分钟（评审修订：原 10 分钟恢复过慢）。

竞态防护（评审修订）：巡检重置使用条件更新 `UPDATE ... SET status='FAILED' WHERE id=? AND status='RUNNING' AND heartbeat_at < ?` 并校验影响行数；Worker 每次心跳更新后校验自身执行仍为 RUNNING，发现被重置立即终止本地执行（放弃式退出），杜绝双 Worker 并发处理同一执行。NODE_LOST 错误码可重试。

#### FR-EXE-08 产物归档与保留期（P0 / M2）

产物文件上传存储后端，路径规范 `artifacts/{yyyy}/{MM}/{dd}/{taskId}/{execId}/{artifactKey}.{ext}`。artifactKey 生成规则限字母数字下划线，拼接路径前做白名单校验，防路径遍历（评审修订）。数据库存逻辑 URI（hp://{storageId}/{path}）。保留期按存储后端与任务两级配置，默认 90 天。清理任务每日删除过期产物文件，执行日志保留并标记"产物已清理"。模板版本文件永不自动清理。

#### FR-EXE-09 数据就绪预检（P2 / M5）

REPORT 任务可选配置预检：探测 SQL（同一数据源，轻量查询）加期望条件（如行数大于 0、标志值等于 1）。触发后先执行预检，不满足则在等待窗口内（默认 30 分钟，间隔 5 分钟）轮询重查，窗口耗尽按任务配置处理：放弃本次执行（记录 SKIPPED_NOT_READY，不计入失败告警）或强制执行。预检等待不占用 Worker 槽位（挂起态重入队）。与 FR-API-01 互补：前者平台自查，后者外部通知。

#### FR-EXE-10 临时文件清理（P0 / M2）

渲染产生的本地临时文件在执行结束（无论成败）时删除。巡检任务每小时清理临时目录中修改时间超过 24 小时的残留文件。

### 4.8 监控告警

#### FR-ALR-01 ALERT 任务定义（P1 / M4b）

配置项：监控数据集（单条 SQL，期望返回一行一列；界面要求用户指定数值列，默认第一列，列类型必须可比较）、条件表达式（运算符 > >= < <= == !=，右值为常量或参数）、防抖次数 N（连续 N 次命中才跃迁 TRIGGERED，默认 1）、评估周期 cron（最小 1 分钟）、通知渠道与消息模板（可引用触发值、阈值、时间变量）。

取值边界（评审修订）：查询返回多行取第一行，其余忽略并记 WARN；返回 0 行按 miss；结果为 NULL 按 miss，状态面板显示"最近值：NULL"。

#### FR-ALR-02 状态跃迁通知（P1 / M4b）

状态仅 OK 与 TRIGGERED 两种，持久化在告警状态表。仅跃迁时发送通知：OK 到 TRIGGERED 发告警，TRIGGERED 到 OK 发恢复。持续 TRIGGERED 期间不重复通知（语义参照 Redash Alerts）。

一致性保障（评审修订）：状态表含 task_version_id 与 consecutive_count；计数与状态更新走乐观锁（条件 UPDATE 校验旧值），并发评估不丢计数；任务配置版本变更（阈值或 N 修改）时重置防抖计数并在面板提示。查询失败按 FR-EXE-04 重试，重试耗尽发系统告警，业务状态保持不变。告警升级（TRIGGERED 持续 N 分钟后追加通知）列入远期。

#### FR-ALR-03 告警状态面板（P1 / M4b）

ALERT 任务列表展示当前状态、最近评估值、最近跃迁时间。详情页展示跃迁历史时间线与评估记录。提供"测试触发"：按当前数据评估一次并强制发送通知到所选测试渠道，不影响正式状态。

#### FR-ALR-04 系统失败告警（P0 / M4a）

平台自身事件推送至系统级告警渠道（独立配置，指向运维群与运维邮箱）。事件：任务重试耗尽、任务连续失败 N 次（默认 3，仅统计执行层失败，ALERT 正常 miss 不计入，评审修订）、任务超期未触发（超过 2 个周期）、渲染进程超时、存储上传失败、数据源连续不可用。去重静默：同一（任务，错误码）30 分钟内仅发一次。系统告警不进重试队列，发送失败仅记日志。

### 4.9 个性化分发（FANOUT）

#### FR-FAN-01 分发清单（P1 / M5）

REPORT 任务可选启用 FANOUT。清单来源二选一：
1. 静态清单：界面表格维护，每行为接收目标与参数组
2. 清单 SQL：一条 SQL，约定列名（评审修订）：`fanout_key`（行标识，必填）、`receiver`（接收目标，必填）、其余列全部注入为子执行参数。receiver 的语义按绑定渠道解析：邮件渠道为邮箱地址；企微群渠道为 @ 成员标识（userid 或手机号，与 FR-CH-02 对齐）；群渠道未配 receiver 列时所有行发同一群仅参数不同。清单 SQL 走同一套校验、保护与审计

清单行字段可在产物模板中引用（水印文字、正文称呼）。清单为空复用空结果策略（FR-TSK-07）；清单行按 fanout_key 与各参数列拼接哈希去重，重复行保留首条并记 WARN（评审修订）。

#### FR-FAN-02 子执行扇出（P1 / M5）

父执行读取清单后为每行创建子执行（PENDING，parent_exec_id 加 fanout_key，唯一键防重）。子执行数量上限默认 200，超限父执行直接失败并告警。子执行进入普通队列并行处理，各自独立重试、幂等、日志。单个子执行失败不影响其他子执行。

#### FR-FAN-03 父执行汇总（P1 / M5）

父执行扇出后置 WAIT_CHILDREN 并释放 Worker（评审修订：不占槽位轮询）。每个子执行到达终态时以条件更新原子递增父执行的完成计数，最后一个完成的子执行触发父执行终态汇总：全部成功 SUCCESS，部分成功 PARTIAL_SUCCESS（详情列出失败行与原因），全部失败 FAILED。汇总幂等（条件更新保证仅生效一次）。执行详情页提供父子视图，支持按状态筛选与仅重跑失败子执行。

### 4.10 存储

#### FR-STO-01 存储抽象与逻辑 URI（P0 / M2）

统一 FileStorage 接口（put / get / delete / exists / presignedUrl）。数据库存逻辑 URI hp://{storageId}/{path}，物理地址变更不影响历史记录。支持多后端并存，模板与产物可分别指定后端。

#### FR-STO-02 本地存储（P0 / M2）

开发与小规模场景使用。集群部署时界面警示"本地存储不共享，多节点场景请选择对象存储"。

#### FR-STO-03 S3 兼容存储（P0 / M2）

基于 AWS S3 SDK v2，覆盖阿里云 OSS 与 MinIO。配置项：endpoint、region、bucket、accessKey（加密存储）、路径前缀。presignedUrl 用于产物在线下载与钉钉图片链接（FR-CH-08），时效默认 5 分钟可配。

#### FR-STO-04 HDFS 存储（P2 / M5）

目标环境（已确认）：自建 Apache Hadoop 3.2.4，未启用 Kerberos，走 simple 认证（仅需 NameNode 地址与代理用户配置，无 keytab 管理）。

实现约束：
1. 独立 Maven 模块按条件加载，hadoop-client 版本与服务端对齐 3.2.x
2. Hadoop 3.2.4 传递依赖为旧版 Jackson/Guava，与 Spring Boot 3（Jackson 2.15+）存在冲突风险：模块内对 hadoop-client 做传递依赖排除并单独 shade，或改用 hadoop-client-runtime（shaded 发行版），M5 启动时以集成测试验证二选一
3. 文件读写走 FileStorage 统一接口，路径规范与保留期策略同其他后端

### 4.11 安全与审计

#### FR-SEC-01 凭据加密（P0 / M1）

数据源密码、渠道 webhook 与 secret、SMTP 密码、存储 accessKey 全部 AES-GCM 加密存储。密文格式（评审修订，M1 即冻结）：key_id + nonce + ciphertext + tag，Base64 编码入库，为密钥轮换预留 key_id 位，避免后续数据迁移。

主密钥托管（已确认）：环境变量 `HP_MASTER_KEY` 注入（公司无 KMS），不入代码库与数据库。配套防护写入部署手册：经 systemd 单元文件或权限 600 的 env 文件设置（不用命令行参数，避免 ps 泄露）；不进 shell history 与 CI 日志；应用日志禁止打印；Docker 部署经 secret/env 注入且不写入镜像层。轮换机制：双密钥并存解密、单密钥加密，M4a 交付轮换工具。

#### FR-SEC-02 认证与 RBAC（P0 / M2，评审修订提前）

Sa-Token 实现登录会话与三角色 RBAC（矩阵见 2.2）。M1 单管理员账号；M2 起启用多用户、三角色与数据源级授权（FR-DS-05）。理由：M2 交付 Excel 文件外发能力后，单管理员模式意味着密码泄露即全部数据源可被导出外发。会话超时默认 8 小时。账户安全增强（锁定、登录日志、事件通知）见 FR-SEC-05（M4a）。

#### FR-SEC-03 SQL 审计（P0 / M1）

记录每次 SQL 执行：数据预览（scene = PREVIEW）、试运行（TRIAL）、正式执行（EXEC）、ALERT 评估（ALERT_EVAL）、FANOUT 清单查询（FANOUT_LIST）、校验失败尝试（VALIDATION_FAILED，评审修订）。字段：操作人或执行 ID、数据源、SQL 原文、参数、返回行数、耗时、场景、客户端 IP。不记录结果集内容。参数 JSON 中标记为敏感类型的参数值脱敏存储（评审修订）。只增不改，保留 180 天，查询页 M4a 交付（M1 建表并写入，评审修订：审计数据不可事后补录，落库必须随主链路）。

#### FR-SEC-04 配置变更审计（P1 / M4a）

所有配置实体（数据源、任务、模板、渠道、白名单、用户、配额）的增删改记录：实体类型与 ID、操作人、动作、字段级 diff（敏感字段仅记"已变更"）、IP、时间。只增不改，ADMIN 可查询。

#### FR-SEC-05 账户安全（P1 / M4a）

登录失败 5 次锁定账户 15 分钟（参数可配）；登录日志（成功与失败，含 IP 与 User-Agent）；敏感事件邮件通知管理员（改密、锁定、白名单变更、授权变更）。IP 访问白名单与 HTTPS（含双向认证）由部署层网关实现，写入部署手册。

#### FR-SEC-06 展示脱敏（P1 / M2）

非 ADMIN 角色：渠道 webhook 与密钥脱敏（保留域名与末 4 位）；数据源密码永不下发。VIEWER：隐藏 SQL 原文、参数、数据源连接信息。（评审修订：随 RBAC 提前至 M2。）

### 4.12 平台运营

#### FR-OPS-01 今日概览（P1 / M4b）

平台首页三块内容：今日执行汇总（总数、成功、失败、进行中）；未来 1 小时触发时间线；ALERT 任务状态一览（TRIGGERED 置顶）。

#### FR-OPS-02 错误码字典与修复建议（P1 / M4a）

错误码分段：DS（数据源）、SQL（语句与参数）、TPL（模板与沙箱）、RD（渲染）、PUSH（渠道）、STO（存储）、SYS（平台）。执行日志与告警消息展示错误码、用户可读解释、建议动作。字典随版本维护，前端按错误码渲染修复建议卡片。本文档已引用的错误码：DS-001/002/003、SQL-004/005、TPL-003/010、RD-006、PUSH-011/021/022、SYS-005、NODE_LOST、SKIPPED_NOT_READY。

#### FR-OPS-03 配额治理（P2 / M4a）

可配限额：单用户任务数上限（默认 50）、渲染并发（节点级信号量默认 2，全局上限默认 4，评审修订：明确两级关系，全局上限跨节点由 Redis 计数实现）、测试发送每日上限（默认 20 每用户）、FANOUT 子执行上限（默认 200 每次）、单数据源连接池总量（默认 40）。达到限额时操作被拒绝并提示。

#### FR-OPS-04 运营指标面板（P2 / M5）

平台级指标：任务成功率趋势、渠道吞吐与失败率、渲染耗时分布、存储用量与保留期预警、活跃任务与用户数。数据来自执行日志每日聚合。

#### FR-OPS-05 双模式与场景模板（P0 / M1，v1.2 新增）

落地 1.6 渐进披露原则的界面能力：

1. **简单模式（默认）**：导航仅六项（今日、推送任务、数据源、推送内容模板、推送渠道、执行记录）；界面用语遵循 1.6 术语对照表；不展示未交付里程碑的功能入口
2. **场景模板入口**：新建任务首先出现场景卡片，预置四个场景，选择后全部配置带出，用户只改 SQL 与群：
   - 日报发群（摘要卡片 + 表格图片，每天固定时间）
   - 明细附件（摘要卡片 + Excel 附件）
   - 指标监控提醒（ALERT，随 M4b 显示）
   - 按人分发（FANOUT，随 M5 显示）
   - 自定义（进入专家模式五步向导）
3. **3 步简单向导**：数据查询（选库、写 SQL、预览，日期条件自动带入数据日期）→ 推送内容（摘要卡片 / 表格图片 / Excel 附件勾选卡片）→ 群和时间（渠道勾选 + 常用时间快捷项）。末步展示人话配置摘要，提供"发到测试群"与"上线"
4. **专家模式**：完整导航与五步向导（FR-TSK-01）、全部高级配置面板；顶栏一键切换，切换不丢数据
5. **高级折叠**：专家向导第 4 步中 misfire、抖动、预检、审核、按人分发收进"高级"折叠面板，默认收起

验收：
1. 新用户从登录到用"日报发群"场景把一个任务发到测试群，全程点击不超过 10 次、不出现 1.6 对照表左列术语
2. 简单模式创建的任务在专家模式可见全部默认配置，修改后回到简单模式数据一致
3. M1 构建的界面不出现 ALERT、按人分发、审核入口

### 4.13 开放接口

#### FR-API-01 入站触发 API（P1 / M4b）

`POST /api/v1/tasks/{taskKey}/trigger`，Header 携带任务级 token（任务详情页生成与吊销，哈希存储）。请求体可覆盖参数（含 bizDate）与幂等键。幂等语义（评审修订）：（task_id, idempotency_key）唯一，重复请求返回原执行 ID 而非新建执行。行为与手动触发一致（trigger_type 为 API）。限流：单任务默认 10 次每分钟。全部调用写审计。

#### FR-API-02 执行状态查询 API（P2 / M5）

`GET /api/v1/execs/{execId}`，任务级 token 鉴权，返回状态、产物下载地址（presignedUrl）、错误信息。供外部系统轮询触发结果。

## 附录 A 原型说明

交互原型位于 `docs/prototype/index.html`，单文件 HTML，浏览器直接打开，无外部依赖。支持三种角色登录演示权限矩阵差异。

v1.2 起原型默认进入**简单模式**（对应 FR-OPS-05）：六项导航、场景模板建任务入口、3 步简单向导、生活化术语。顶栏可切换**专家模式**查看全量功能：今日概览、任务详情抽屉（版本、锁定版本、入站 API、手动触发）、五步向导、监控告警面板、分发清单与父子执行、审核工作台、审计中心、系统设置等全部页面。原型使用仿真数据，不对接后端；为便于评审，专家模式展示了 M4b/M5 功能并标注里程碑，真实产品按 1.6 原则随里程碑渐显。

已知差异（随下一版原型迭代）：钉钉渠道产物绑定能力校验交互待补；简单模式执行记录页复用专家版详情抽屉，术语未完全对照。

## 附录 B 术语表

| 术语 | 定义 |
|---|---|
| 数据集（Dataset） | 任务内一个数据源加一条 SQL 加参数定义的查询单元 |
| 产物（Artifact） | 数据集经模板渲染后的输出物，四种类型：Markdown、Excel、图片、PDF |
| 渠道（Channel） | 推送目的地配置，五类：企微、钉钉、飞书群机器人，邮件，通用 Webhook |
| 渠道绑定 | 任务内"哪个渠道发哪些产物、以什么消息类型"的关联配置 |
| bizDate | 业务日期，默认等于触发日期减 1 天，可被手动触发、API 与 FANOUT 覆盖 |
| 任务配置快照 | 任务某次保存时的完整配置 JSON，不可变，执行记录关联具体快照 |
| 固版（Pin） | 任务锁定使用某一历史快照运行，编辑不影响线上 |
| FANOUT | 个性化分发，按分发清单把一个任务扇出为多个子执行 |
| fanout_key / receiver | 分发清单的行标识列与接收目标列，其余列注入为子执行参数 |
| 状态跃迁 | ALERT 任务在 OK 与 TRIGGERED 之间的变化，仅跃迁时发通知 |
| 逻辑 URI | 平台统一文件引用格式 hp://{storageId}/{path}，与物理存储解耦 |
| 数据预览 / 试运行 / 测试发送 | 三种验证动作：单条 SQL 试跑（无执行记录）/ 全链路渲染不推送 / 完整推送到测试目标 |
| misfire | Quartz 术语，触发点因节点故障等原因错过；本平台策略见 FR-EXE-01 |
| 幂等键 | 防重复动作的唯一标识：推送四元组、调度唯一索引、API 触发键 |
| 简单模式 / 专家模式 | 同一份任务配置的两套界面视图：简单模式默认极简路径，专家模式暴露全部配置（FR-OPS-05） |
| 场景模板 | 预置好的完整任务配置骨架（日报发群、明细附件等），用户只改 SQL 与群 |
| 渐进披露 | 一级设计原则（1.6）：默认极简、高级折叠、能力随里程碑渐显、术语生活化 |
